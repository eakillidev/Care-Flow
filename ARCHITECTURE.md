# CareFlow Architecture

CareFlow is a focused full-stack application with one Angular frontend, one Go API, and one PostgreSQL database. It deliberately uses a conventional modular monolith rather than distributed infrastructure.

## Angular + Go

Angular provides typed forms, routing, HTTP integration, and testable standalone UI components for the coordinator and caregiver workflows. Go keeps the API small, explicit, and easy to deploy while offering strong concurrency and standard-library HTTP support; chi adds lightweight REST routing without a framework-heavy application model.

## PostgreSQL

Users, patients, caregiver assignments, and visits have relational constraints and transactional state changes. PostgreSQL fits those relationships, preserves visit history through foreign keys, and supports efficient filtered dashboard and scheduling-conflict queries. The API uses pgx/pgxpool and explicit parameterized SQL instead of an ORM.

## Backend Structure

- HTTP handlers decode requests, read authenticated identity, and map errors to responses.
- Services enforce scheduling, ownership, state-transition, and EVV business rules.
- Repositories isolate SQL and PostgreSQL access.
- Authentication middleware verifies JWTs and supplies a typed request identity.
- The EVV package owns geographic distance, time-window validation, and stable exception reasons.

This separation keeps transport and database concerns out of the core rules without adding unnecessary framework abstractions.

## EVV Validation

Check-in and check-out timestamps are generated by the server. The API verifies that the JWT caregiver owns the visit, enforces `scheduled -> in_progress -> completed`, and uses conditional database updates to prevent duplicate concurrent transitions. Check-in evaluates the configured time tolerance and both actions evaluate distance from the patient's coordinates against the configured geofence. Rule failures record EVV exceptions while valid state transitions continue.

## Security

Passwords are stored as bcrypt hashes. HS256 JWT access tokens carry the user ID and role, and middleware distinguishes authentication from coordinator/caregiver authorization. Caregiver ownership always comes from the verified JWT context; clients cannot select or override their caregiver ID.

## Testing

Unit tests cover password, JWT, middleware, configuration, and EVV calculations. PostgreSQL-backed integration tests exercise repositories and complete authentication, scheduling, dashboard, ownership, and EVV HTTP workflows in isolated schemas. Angular service and component tests cover login, guards, API requests, dashboards, geolocation states, and EVV actions.

## Intentional Scope Decisions

CareFlow intentionally excludes AWS, Kubernetes, Redis, message queues, FHIR/HL7, GenAI, billing, payroll, and claims. Those systems are not required to demonstrate the portfolio application's core full-stack scheduling, authorization, persistence, and EVV workflow, and excluding them keeps the implementation understandable and verifiable.
